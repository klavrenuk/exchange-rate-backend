# Exchange Rate Backend

Бэкенд-сервис для автоматического получения курсов валют НБРБ и сбора графиков IEA с отправкой по email.

Только бэкенд (FastAPI). Фронтенд — в соседнем каталоге `../exchange-rate-frontend`; общая инструкция — `../README.md`.

## Стек
- Python 3.11+, FastAPI, SQLAlchemy 2.0 (async), SQLite (aiosqlite)
- APScheduler для расписания
- httpx + BeautifulSoup для парсинга
- Playwright для скриншотов страниц IEA (опционально)
- openpyxl для Excel-отчётов
- smtplib для отправки почты

## Установка
```powershell
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
playwright install chromium
```

Для Linux/Mac активация: `source .venv/bin/activate`.

Все команды выполняются из корня репозитория: относительные пути (`./data`, `.env`) считаются от текущего каталога.

## Параметры (.env)

Скопируйте шаблон и отредактируйте:

```powershell
Copy-Item .env.example .env
```

`.env` читается при старте приложения — после изменения нужен перезапуск.

Обязательных параметров нет: у всех есть значения по умолчанию, и проект запустится без `.env`. Для реальной работы нужно задать как минимум параметры почты.

### База и каталоги
| Параметр | По умолчанию | Назначение |
|---|---|---|
| `DATABASE_URL` | `sqlite+aiosqlite:///./data/db.sqlite3` | Подключение к SQLite |
| `DATA_DIR` | `./data` | Корневой каталог данных |
| `REPORT_DIR` | `./data/reports` | Excel-отчёты |
| `CHART_DIR` | `./data/charts` | Скачанные графики IEA |

### Почта (нужно для реальной отправки)
| Параметр | Пример | Назначение |
|---|---|---|
| `SMTP_HOST` | `smtp.yandex.ru` | SMTP-сервер |
| `SMTP_PORT` | `465` | Порт |
| `SMTP_USER` | `user@yandex.ru` | Логин |
| `SMTP_PASSWORD` | `app-password` | Пароль приложения |
| `SMTP_USE_SSL` | `true` | SSL с первого байта (обычно порт 465) |
| `SMTP_USE_TLS` | `false` | STARTTLS (обычно порт 587) |
| `MAIL_FROM` | `user@yandex.ru` | Отправитель |
| `MAIL_TO` | `a@example.com,b@example.com` | Получатели через запятую |
| `MAIL_DRY_RUN` | `true` | Не отправлять письма, только писать в лог |
| `MAIL_SUBJECT_PREFIX` | `[ExchangeRates]` | Префикс темы письма |

Для Яндекса: порт 465 → `SMTP_USE_SSL=true`, `SMTP_USE_TLS=false`; порт 587 → `SMTP_USE_TLS=true`, `SMTP_USE_SSL=false`.

### Расписание
| Параметр | По умолчанию | Назначение |
|---|---|---|
| `SCHEDULER_ENABLED` | `true` | Включить планировщик |
| `TZ` | `Europe/Minsk` | Таймзона расписания |
| `SCHED_NBRB_UPDATE_CRON` | `0 9 * * *` | Обновление курсов НБРБ |
| `SCHED_REPORT_CRON` | `0 18 * * *` | Excel-отчёт и отправка |
| `SCHED_IEA_CHECK_CRON` | `0 10 * * *` | Проверка/скачивание/отправка IEA |

Формат cron — 5 полей: `минута час день месяц день_недели`. Время трактуется в `TZ`.

### НБРБ
| Параметр | По умолчанию | Назначение |
|---|---|---|
| `NBRB_API_BASE` | `https://api.nbrb.by` | Базовый URL API |
| `NBRB_HISTORY_FROM` | `2000-01-01` | Начало истории при загрузке без `from_date` |
| `NBRB_LOAD_BATCH_DAYS` | `365` | Размер батча при загрузке истории |

### IEA
| Параметр | По умолчанию | Назначение |
|---|---|---|
| `IEA_CATALOG_URL` | `https://www.iea.org/data-and-statistics/charts` | Каталог графиков |
| `IEA_DOWNLOAD_SCREENSHOT` | `true` | Делать скриншоты через Playwright |

`APP_HOST` и `APP_PORT` из `.env.example` кодом не используются — host и port задаются аргументами `uvicorn`.

## Инициализация БД

Таблицы создаются автоматически при старте приложения (`init_db()` в lifespan). Вручную:

```powershell
python -m app.core.init_db
```

Миграций нет, используется `create_all`.

## Запуск

```powershell
uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

Swagger UI: http://127.0.0.1:8000/docs

При `SCHEDULER_ENABLED=true` планировщик стартует в том же процессе. `--reload` перезапускает приложение при изменении кода (планировщик при этом тоже перезапускается).

## Как проверить работу без ожидания следующего дня

Планировщик не нужно ждать — все задачи доступны как ручные эндпоинты. Вызовы можно делать из Swagger или curl.

### Вариант 1. Всё сразу

```powershell
curl.exe -X POST http://127.0.0.1:8000/tasks/run-all
```

Выполняет: синхронизацию валют НБРБ, курсы на сегодня, Excel-отчёт с отправкой, затем discover/download/send для IEA. Ошибки отдельных шагов не прерывают остальные.

### Вариант 2. По шагам

1. Справочник валют НБРБ
```powershell
curl.exe -X POST http://127.0.0.1:8000/nbrb/sync-currencies
```

2. История курсов (по умолчанию с `NBRB_HISTORY_FROM` по сегодня). Можно ограничить валютой и диапазоном
```powershell
curl.exe -X POST "http://127.0.0.1:8000/nbrb/load-history?cur_abbr=USD&from_date=2020-01-01&to_date=2024-12-31"
```

Загрузка идёт батчами по `NBRB_LOAD_BATCH_DAYS`, полная история по всем валютам может занять много времени. Повторный вызов безопасен: дубли не создаются (уникальный ключ `currency_id + date`).

В демонстрационной базе загружено **76 623 курса за 2020-01-01 … 2026-10-26** (файл `data/db.sqlite3` не входит в git). Период 1991–2019 не загружен: это заметно увеличивает объём БД и время первичной загрузки. Продолжить можно командой:

```powershell
curl.exe -X POST "http://127.0.0.1:8000/nbrb/load-history?from_date=1991-01-01"
```

3. Курсы на сегодня
```powershell
curl.exe -X POST http://127.0.0.1:8000/nbrb/update-today
```

4. Excel-отчёт за сегодня + отправка
```powershell
curl.exe -X POST http://127.0.0.1:8000/nbrb/report-and-send
```

5. IEA: найти графики в каталоге
```powershell
curl.exe -X POST http://127.0.0.1:8000/iea/discover
```

6. IEA: скачать новые графики (HTML, CSV из data-атрибутов, скриншот)
```powershell
curl.exe -X POST http://127.0.0.1:8000/iea/download-new
```

7. IEA: отправить неотправленные графики
```powershell
curl.exe -X POST http://127.0.0.1:8000/iea/send-new
```

### Вариант 3. Проверить именно планировщик

Временно поставьте запуск через пару минут, например:

```dotenv
SCHED_NBRB_UPDATE_CRON=*/2 * * * *
```

Перезапустите приложение и подождите 2 минуты. Затем проверьте `GET /status/jobs` — появится запуск `nbrb.update_today` / `nbrb.sync_currencies`. После проверки верните прежнее значение cron и перезапустите приложение.

### Что проверить в результате

| Проверка | Ожидаемый результат |
|---|---|
| `GET /health` | `{"status": "ok"}` |
| `GET /status/overview` | Ненулевые счётчики валют/курсов/графиков, список последних задач |
| `GET /status/jobs` | Задачи со статусом `success`, без `error_text` |
| `data/reports/` | Файл `nbrb_rates_<дата>.xlsx` |
| `data/charts/<slug>/` | `page.html`, `screenshot.png`, `data.csv` |
| `GET /nbrb/rates?ondate=YYYY-MM-DD` | Курсы на указанную дату |
| `GET /iea/charts` | Список графиков с признаком `sent` |

API НБРБ возвращает курс на календарную дату; в выходные обычно повторяется значение последнего рабочего дня. Если на запрошенную дату курсов в базе нет, отчёт автоматически берёт последнюю доступную дату не позже запрошенной. Файл и заголовок содержат фактическую дату данных.

### Безопасная проверка отправки

Оставьте `MAIL_DRY_RUN=true` — письма не уходят, а в лог пишется `[DRY RUN] Would send email...`. Для реальной отправки задайте SMTP-параметры и `MAIL_DRY_RUN=false`.

## Расписание

При `SCHEDULER_ENABLED=true`:
- `SCHED_NBRB_UPDATE_CRON` — синхронизация валют и курсы на сегодня (по умолчанию 09:00)
- `SCHED_REPORT_CRON` — Excel-отчёт и отправка (по умолчанию 18:00)
- `SCHED_IEA_CHECK_CRON` — discover + download + send для IEA (по умолчанию 10:00)

## Особенности
- Ошибки одного источника не останавливают остальные — шаги обёрнуты в try/except, статусы пишутся в `job_runs`
- Состояние хранится в БД — после перезапуска приложение знает, что уже скачано и отправлено
- Уже отправленные графики IEA не пересылаются повторно (таблица `sent_charts`)
- Дубли курсов исключены уникальным индексом `(currency_id, date)`
- Изменённые курсы обновляются при повторном `update-today`
- Все пути и параметры настраиваются через `.env` без изменения кода

## Ограничения и что не реализовано
- История за 1991–2019 не загружена; команда продолжения указана выше.
- Для реальной отправки почты нужен рабочий SMTP и пароль приложения. По умолчанию включён `MAIL_DRY_RUN=true`.
- IEA отправляет один вложенный файл на график — `data.csv` (в каталоге также лежат `page.html` и `screenshot.png`).
- Планировщик работает внутри процесса `uvicorn`; отдельный автозапуск ОС/служба не настроены.
- При частичных ошибках загрузки история и IEA пишут количество сбоев и список ошибок в `details_json` задачи; успешная часть сохраняется.
